# QUIC 会话可靠性与桌面设置

服务端继续在一个 UDP 端口上运行，默认 4242。两端通过一次性邀请配对，固定服务端证书，凭据仍保存在系统凭据存储。旧版 QUIC v2 客户端能解析更新后的握手，新增的屏幕方向和平台提示会在对端支持时显示。

- 客户端在网络故障后重试，间隔从 1 秒开始加倍，最多 8 秒并带少量抖动。重试前会读取已保存的地址。主动取消、关闭自动重连、设备撤销或同设备会话被替换都会停止重试。
- QUIC 控制流传输按钮、键盘、滚轮和功能配置，数据报传输绝对光标位置。控制序号确保先定位再应用点击。心跳超时、连接关闭和会话替换会释放已经注入的输入。
- 捕获层分别记录鼠标和键盘的按下归属。禁用键盘时，被控端释放按键后确认设置。松开事件仍交给原归属方处理，本地按住按键或按钮期间不会切入远端。
- 剪贴板使用独立 QUIC 流。禁用时废弃当前流代次，取消时无需等待系统剪贴板调用返回。已经进入系统调用的写入由操作系统完成。
- 窗口、托盘和退出流程读取会话状态。停止通过独立信号取消连接、控制发送和等待；界面仅回收已结束的线程。
- GUI 的 `config.json` 保存版本化偏好和最后成功的角色。客户端恢复时按已配对设备 ID 读取当前地址与证书。配对和转发选项仍保存在原设备库。配置写入使用同目录临时文件并原子替换。
- 开机启动使用当前用户的 macOS LaunchAgent 或 Windows Run 项，默认关闭。托盘开启时关窗隐藏。第二次启动读取独立的唤醒地址并唤起已有窗口，Windows 进程不必读取上锁的文件。

## 验证

本地使用 `cargo test --locked --all-features --lib --tests`。回归包括 QUIC 配对及证书校验、撤销、同设备替换、地址更新后重连、重连取消、静止和失联、点击与移动排序、输入释放、剪贴板取消、设置保存和回退、单实例唤醒及关闭窗口等待后台清理。Windows 和 macOS 均由 CI 构建并运行测试。真实双机手感及实际登录启动需要真机验证。
